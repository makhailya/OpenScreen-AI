# OpenScreen AI

OpenScreen AI — настольный помощник для разработчика. Сейчас приложение позволяет задать текстовый вопрос и получить потоковый ответ от локального сервера Ollama.

> В текущей версии нет голосового ввода, захвата экрана, overlay и глобальных горячих клавиш. Распознавание речи (STT) и тестирование производительности пока не входят в готовые возможности приложения.

## Возможности и статус

### Реализовано в текущем текстовом приложении

- Окно чата на PySide6 с вводом запроса, выводом ответа и кнопкой отмены.
- Потоковая генерация ответа через локальный Ollama API.
- Выполнение запроса в отдельном Qt потоке, чтобы ожидание не блокировало UI.
- Проверка локального адреса Ollama, имени модели и положительного таймаута.
- Модульные тесты с подменным HTTP-транспортом; для них не требуется запущенный Ollama.

### Не реализовано в приложении

- В основном приложении нет STT-пакета с Parakeet и Silero VAD, поэтому голосовой сценарий недоступен.
- Инфраструктура тестирования производительности и адаптер для запуска STT на аудиофайлах не входят в текущую версию. Скорость распознавания не измерялась.

### Запланировано

- Окно overlay и системное управление им.
- Захват экрана, горячие клавиши и связанные разрешения macOS.
- Подключение STT к пользовательскому сценарию, если этот сценарий будет включён в план.
- CI и упакованный macOS application bundle.

## Архитектура

При запуске `main()` загружает конфигурацию, создаёт провайдер Ollama, передаёт его в `Assistant`, а затем создаёт главное окно. `Assistant` использует интерфейс `TextProvider`; текущая реализация этого интерфейса — Ollama.

Поток запроса:

    PySide6 MainWindow → GenerationWorker (QThread + asyncio)
                       → Assistant / TextProvider
                       → OllamaProvider → локальный Ollama /api/generate

Ответы Ollama читаются построчно в формате JSONL и передаются в интерфейс по мере получения. При отмене worker отменяет задачу asyncio через её цикл событий. В приложении нет захвата экрана, голосового ввода, overlay-окна или облачного провайдера.

## Требования

- Python 3.12 или новее — нижняя граница из pyproject.toml.
- macOS — целевая платформа проекта. Проверенная матрица совместимости с Apple Silicon и Intel отсутствует.
- Локально установленный Ollama и модель, совместимая с Ollama API.

## Установка

Из корня клонированного проекта создайте и активируйте виртуальную среду, затем установите приложение и инструменты разработки:

    python3.12 -m venv .venv
    source .venv/bin/activate
    python -m pip install -e ".[dev]"

Если .env ещё не существует, создайте его из примера:

    cp .env.example .env

Команда устанавливает проект в режиме разработки вместе с инструментами проверки.

## Запуск

Установите Ollama по официальной инструкции и запустите сервер. Затем загрузите совместимую модель (пример):

    ollama serve
    ollama pull qwen2.5-coder:7b

Запустите приложение из активированного окружения:

    python -m openscreen_ai.main

После установки доступна также консольная команда:

    openscreen-ai

## Конфигурация

Настройки читаются из `.env` с помощью `python-dotenv` и проверяются до создания провайдера.

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | Адрес локального Ollama. Разрешён только loopback-адрес; имя пользователя и пароль в URL запрещены. |
| `OLLAMA_MODEL` | `qwen2.5-coder:7b` | Точное имя уже установленной модели Ollama. |
| `OLLAMA_TIMEOUT_SECONDS` | `120` | Положительный конечный таймаут запроса. |

Не помещайте секреты в README или Git. Текущий провайдер рассчитан на локальный адрес Ollama; удалённые и облачные провайдеры не реализованы.

## Проверка

Из корня проекта:

    ruff check .
    pytest

Дополнительная группа зависимостей `dev` включает Ruff и pytest. Тесты провайдера используют подменный HTTP-транспорт и не требуют запущенного Ollama; заявленный диапазон pytest — `>=8,<9`.

## Известные ограничения

- Голосовой ввод и интеграция STT в пользовательский интерфейс пока не реализованы.
- Нет захвата экрана, overlay-окна, глобальных горячих клавиш, облачных LLM-провайдеров и пакета приложения для macOS.
- Работа с реальным Ollama, Parakeet, устройствами и macOS TCC здесь не подтверждалась.
- Инфраструктура тестирования производительности и измерения STT пока не входят в релиз.
- CI и полная подтверждённая матрица платформ отсутствуют.
- Размер тела ответа провайдера с ошибкой и завершение потока без маркера окончания JSONL требуют отдельной политики обработки.
