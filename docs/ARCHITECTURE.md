# Архитектура MVP

## Слои

- `ui` — окно PySide6, поля ввода/ответа и сигналы Qt. Здесь нет HTTP-запросов.
- `core` — класс `Assistant` и контракт `TextProvider`. Он проверяет вопрос и
  передаёт управление провайдеру, не зная деталей Ollama.
- `providers` — `OllamaProvider`, который отправляет асинхронный HTTP-запрос и
  читает JSON Lines, возвращая текст по фрагментам.
- `services` — пока только пакет-заготовка для будущих системных адаптеров.
- `config` — чтение переменных окружения и `.env`, проверка URL, модели и таймаута.

`main.create_window` выполняет простую ручную сборку зависимостей: конфигурация
попадает в `OllamaProvider`, тот передаётся в `Assistant`, а ассистент — в окно.
Так UI можно тестировать с поддельным провайдером, не подключаясь к Ollama.

## Поток данных

1. UI проверяет, что пользователь ввёл непустой вопрос, и запускает `GenerationWorker`.
2. Worker выполняется в отдельном `QThread` и создаёт свой asyncio event loop.
3. `Assistant` передаёт вопрос провайдеру через интерфейс `TextProvider`.
4. `OllamaProvider` отправляет `POST /api/generate` на адрес из конфигурации.
5. Ответ читается частями; Qt-сигнал передаёт каждый фрагмент главному потоку.
6. При отмене worker отменяет coroutine. При закрытии окна оно ждёт завершения
   отмены, затем закрывается, не уничтожая работающий поток.

Конфигурация разрешает только loopback-адрес Ollama (`localhost` или loopback IP),
поэтому запрос нельзя случайно отправить на внешний хост. В MVP нет захвата экрана,
микрофона, облачного провайдера или выполнения команд из ответа модели.
